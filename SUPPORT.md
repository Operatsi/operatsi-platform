## 2. When to Use What

### File a GitHub Issue
- You encountered a reproducible bug in the client or server runtime.
- You identified an accessibility defect (see [ACCESSIBILITY.md](ACCESSIBILITY.md)).
- You have an engineering feature proposal with clear user rationale.

### Contact Enterprise Support
- Production workspace outage or degradation.
- Billing, subscription, invoice, or seat quota inquiries.
- Dedicated SSO/SAML configuration and enterprise audit log access.

### Report to Security
- Suspected authorization bypass or privilege escalation.
- Firestore rule boundary or cloud browser sandbox concerns.
- Never report potential exploits on the public GitHub issue tracker.

---

## 3. Best Practices for Opening Support Tickets

To help our engineering team assist you as quickly as possible, please provide:
1. **Clear Summary**: A concise description of the issue or question.
2. **Environment Details**: Browser and version, Operating System, Node.js version.
3. **Step-by-Step Reproduction**: Detailed steps to recreate the issue.
4. **Console / Network Logs**: Non-confidential error output or stack traces.
5. **Expected vs Actual Behavior**: Clear description of what happened versus what you expected.
